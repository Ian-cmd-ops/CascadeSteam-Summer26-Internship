## README.md: replace the scheduling section

### How a backup is triggered

`backup-poll.timer` fires every 15 minutes on the N100. It runs `backup-poll.sh` as root.

The script exits at once if today's marker exists. The marker is `/mnt/backups/laptop/.last-success` and holds a date.

If no backup ran today, the script checks port 22 on the laptop. It tries the LAN address first, then the mesh address. If either answers, it starts `rsync-snapshot.service`. If the service exits 0, the script writes today's date to the marker.

`rsync-snapshot.service` runs as ian. It probes the LAN host, then the mesh host, with `ssh ... true`. The first host that accepts the key is the pull source. If neither accepts, the run aborts and the poll retries in 15 minutes.

### Tests

```
sudo apt install bats
bats tests/
```

The tests source the script and call `select_target` with a mock probe. No SSH runs.

### Log

The service writes to `logs/rsync-snapshot.log` inside the repo checkout. The `logs/` directory is ignored by git.

## INSTALL.md: replace the deploy steps

```
git clone <gitea-url> /home/ian/rsync-snapshot
cd /home/ian/rsync-snapshot
bash deploy/deploy-backup-poll.sh
systemctl list-timers | grep backup-poll
```

The deploy script installs the four unit files from `systemd/`, reloads systemd, enables the timer, and disables the retired `rsync-snapshot.timer` and `pull-backup.timer`.

To run a backup now:

```
sudo systemctl start rsync-snapshot.service
tail -5 logs/rsync-snapshot.log
```

## docs/DESIGN: replace the target selection section

### Target selection

Two host names are configured. `LAPTOP_LAN_HOST` is the laptop on VLAN 10. `LAPTOP_MESH_HOST` is the laptop's NetBird peer name.

`select_target` calls `probe_host` on each, LAN first. `probe_host` runs `ssh -o BatchMode=yes -o ConnectTimeout=5 HOST true`. The first host that returns 0 is the target.

This replaces source-IP selection. Source-IP selection read the N100's own address from `ip route get`. That address is always on `10.0.20.X/24`, so the check always chose the LAN host. The mesh branch never ran.

The probe tests three things at once: routing, the SSH host key, and key auth. A foreign network that happens to use `10.0.10.X/24` fails the host-key check and falls through to the mesh. Worst case is a skipped backup, never a pull from the wrong machine.

`select_target` accepts an optional probe function name. Tests pass a mock. Production uses the default.

## docs/TROUBLESHOOTING: add three entries

### `sign_and_send_pubkey: signing failed ... agent refused operation`

The private key file has loose permissions. Run `ls -l ~/.ssh/id_restic`. It must be `-rw-------`. Fix with `chmod 600`, then `ssh-add` again.

### `backup-poll.sh: line N: /run/lock/backup-poll.lock: Permission denied`

The lock file is owned by a different user than the one running the script. The service runs as root. Delete the file and start the service again. Do not run `backup-poll.sh` by hand as ian; it calls `systemctl start`, which needs root.

### `tee: /var/log/rsync-snapshot.log: Permission denied`

`rsync-snapshot.service` runs as ian. `/var/log` is root-owned. Confirm the drop-in is installed:

```
systemctl cat rsync-snapshot.service | grep LOG=
```

It must print the `Environment=LOG=` line. If it is missing, run the deploy script again.
