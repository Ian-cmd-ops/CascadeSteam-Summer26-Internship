# 2026-09-03 — change-gated 15-minute pulls replace once-a-day

Ian's requirement: keep polling every 15 minutes and, whenever the laptop is
reachable, take a snapshot if anything changed. Once-a-day at 02:00 was the
wrong shape; the laptop is usually off then and the poller had to catch up
in the morning.

## What changed

- **One script replaces two.** `laptop-backup.sh` merges `backup-poll.sh`
  and `rsync-snapshot.sh`. The split was where drift came from: the deployed
  `backup-poll.sh` on the N100 still had the `/tmp` lock, i.e. it was older
  than the repo.
- **Change gate.** After the pull, a snapshot is promoted only if a file in
  the work dir has link count 1 (rsync transferred it) or the file count
  differs from `latest` (something was deleted). Otherwise the work dir is
  discarded and nothing is logged. Idle laptop, no new snapshots.
- **Age-based retention** replaces "newest 14": keep everything under 24 h,
  one per day up to 14 days, nothing older. Count-based would have shrunk
  history to a few hours on a busy day.
- **`--delete` added.** Without it, files removed on the laptop live on in
  every snapshot and the gate's count check can never fire on deletions.
- **Quiet by default.** Unreachable and no-change write one line to
  `.last-check`; only snapshots and failures reach the log. ntfy pushes on
  every failure and on the first snapshot of each day, nothing else.
- **Atomic promote + atomic `latest`** (temp symlink, `mv -T`). Orphan
  `.incomplete-*` sweep runs under the lock.
- `rsync-snapshot.timer` (02:00, briefly Mon–Fri 09:30) retired.
  `laptop-backup.timer` every 15 min is the only trigger.

## Values

`LAN=ian@10.0.10.X`, `MESH=lubtop`, `SRC=/` (rrsync on the laptop
scopes to /home/ian), `EXCLUDES=/home/ian/.rsync-excludes`,
`DEST=/mnt/backups/laptop`, `KEEP_DAYS=14`.

## Verified

Timer live on the N100; two back-to-back runs: first promoted a snapshot,
second wrote `nochange`. **unverified**: mesh path with the new script (only
