## Faults found and fixed, in the order they surfaced

1. Laptop: `ssh` printed `agent refused operation` for `~/.ssh/id_restic`. Cause: the key file was mode 0640. `ssh-add` refused to load it, so it was never in the agent. Fix: `chmod 600`.
2. N100: `backup-poll.service` failed on every run with `/tmp/backup-poll.lock: Permission denied`. Cause: a stale lock file in `/tmp` owned by ian, while the service runs as root. Fix: deleted the file. Lock path moved to `/run/lock/backup-poll.lock` in this commit.
3. N100: `rsync-snapshot.service` printed `tee: /var/log/rsync-snapshot.log: Permission denied` on every run. Cause: the unit has `User=ian` and `/var/log` is root-owned. Fix: drop-in `override.conf` sets `LOG=/home/ian/rsync-snapshot/logs/rsync-snapshot.log`. The `chown` step in the old deploy script is removed.
4. N100: `rsync-snapshot.sh` never fell back to the mesh. `select_target` matched `192.168.*` against the N100's own source IP, which is always `10.0.20.X`, so it always chose the LAN host. The mesh branch was dead code. Fix: `select_target` now probes each host with `ssh ... true`, LAN first, then mesh. This supersedes the source-IP selection recorded on 2026-08-14. The requirement is unchanged: LAN when the laptop is at home, mesh when it is not. The probe order enforces it.
